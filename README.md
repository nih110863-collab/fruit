# 새벽앤과일 — 고객관리 & 주문 시스템

회원가입 없이 **명단에서 본인 이름을 고르고 4자리 비밀번호**만 누르면 장보기가 되는
동네 가게 주문 시스템입니다.
고객이 직접 주문할 수도 있고, 주인이 전화·카톡으로 받은 주문을 대신 넣을 수도 있습니다.

- 프레임워크: Next.js 16 (App Router, Server Actions)
- DB: Postgres (운영은 Neon, 로컬은 일반 Postgres 자동 인식)
- 스타일: Tailwind CSS v4

---

## 화면 구성

### 고객 (`/`)

| 경로 | 하는 일 |
| --- | --- |
| `/` | 고객 명단에서 본인 이름 선택 (이름이 많으면 검색창 표시) |
| `/enter/[id]` | 숫자 키패드로 4자리 비밀번호 입력. 처음 오는 분은 이 자리에서 본인이 비밀번호를 정합니다 |
| `/order` | 실시간 주문 롤링 알림 → 특별 구역(타임세일/한정수량세일/베스트) → 카테고리·검색으로 담기 → 담기 전 **"주문내역이 맞습니까?" 최종 확인** → 픽업/배달·픽업시간·주소·메모 → 내 주문 내역 확인 · **당일 주문 수정** · 당일 미입금 주문 취소 |

명단에 없는 사람은 주문할 수 없습니다. 새 고객은 주인이 관리자에서 등록해야 합니다.

### 주인 (`/admin`, 비밀번호 1개)

| 경로 | 하는 일 |
| --- | --- |
| `/admin` | 오늘 주문 건수·매출·미입금·배달 건수, **오늘 준비할 물량 합계**, 수량 임박 알림, 오늘 주문 목록, **설정(주문 마감 시간 · 실시간 알림 예시 데이터)** |
| `/admin/today` | 그날 판매목록 짜기 — 품목함에서 꺼내오기 / 새 품목 즉석 등록 / **직전 판매일 목록 통째로 복사** / 가격·수량제한·순서 수정 / 상단 툴바에서 품목을 체크해 **세일가·세일 시작시간+지속시간·노출 구역을 한 번에 적용** |
| `/admin/orders` | 날짜별 주문, 미입금만 모아보기, 고객별 주문, 입금 확인 토글, 주문 취소·삭제 |
| `/admin/orders/new` | 주인이 고객 대신 주문 입력 (기존 고객 검색 또는 새 고객 자동 등록) |
| `/admin/orders/[id]` | 주문 수정 (품목·수량·수령방법 전부) |
| `/admin/stats` | **매출 통계** — 기간(오늘/최근 7일/최근 30일/이번 달/직접 선택)별 매출·주문건수·평균 객단가·미입금, 일별 판매현황, 품목별 판매현황(날짜를 누르면 그날 품목 리스트만) |
| `/admin/products` | 품목함 — 한 번 등록한 품목을 계속 재사용. **분류는 드롭다운(직접 추가 가능)**, **사진은 직접 업로드 또는 무료 이미지 검색**, 보관함으로 숨기고 다시 꺼내기 |
| `/admin/customers` | 고객 등록·검색, 주문 횟수/누적 금액/미입금 합계, 기본 배달주소·메모, **비번 초기화** |

## 데이터 구조

```
products      품목 마스터 — 한 번 등록하면 계속 재사용
  └ daily_items   판매일별 진열 (sale_date + product_id, 가격·수량제한을 그날 값으로)
customers     닉네임 + 뒷 4자리 (unique), 기본 배달주소·메모, 4자리 비밀번호 해시
orders        주문 (날짜, 픽업/배달, 픽업시간, 주소, 메모, 합계, 입금여부, 상태)
  └ order_items   품목명·단가를 주문 시점 값으로 박제 (나중에 가격이 바뀌어도 기록은 그대로)
```

**품목이 매일 바뀌는 구조**: `products`(마스터)와 `daily_items`(그날 진열)를 나눠서,
품목은 계속 쌓이고 매일 필요한 것만 꺼내 올립니다. 판매목록에서 "새 품목 등록해서 바로 올리기"로
만든 품목도 예외 없이 `products`(품목함)에 먼저 저장된 뒤 그날 목록에 올라가므로,
한 번 등록한 품목은 항상 품목함에 남아 다음에 재사용할 수 있습니다.

**분류(카테고리)**: 자유 입력이 아니라 드롭다운입니다. 과일·채소·정육·수산물 등
기본 음식 분류가 미리 들어있고(`lib/types.ts`의 `DEFAULT_CATEGORIES`), 목록에 없는 분류가
필요하면 "+ 새 분류 직접 입력"으로 그 자리에서 추가할 수 있습니다. 한 번 쓴 분류는
`products.category` 에 남아 다음부터 드롭다운에 자동으로 나타납니다 — 별도 분류 테이블이
없어도 관리자가 계속 늘려갈 수 있는 구조입니다.

**단위 없음**: 모든 품목은 "개"로 통일됩니다. 관리자 화면에서 단위를 고르는 입력은
아예 없고("봉"/"팩"/"모" 같은 구분이 필요 없다는 뜻), 고객·관리자 어느 화면에도 단위가
표시되지 않습니다 (`3개`, `주문됨 5개`처럼 항상 "개"). DB의 `unit` 컬럼 자체는 남아있지만
서버가 항상 `'개'`를 채워 넣고, 화면 어디서도 그 값을 읽지 않습니다.

**고객 비밀번호**: 원문은 저장하지 않고 `SESSION_SECRET` 을 키로 쓴 HMAC-SHA256 해시만 보관합니다.
그래서 주인도 고객의 비밀번호를 볼 수 없고, 잊었을 때는 **비번 초기화**로 지워주면
고객이 다음 접속에서 새로 정합니다. 5번 틀리면 5분간 잠깁니다.

**품목 사진**: 두 가지 방법으로 등록합니다.

1. **직접 업로드** — 사진을 고르면 브라우저가 정사각형으로 잘라 900px JPEG 으로 줄인 뒤 올립니다
   (보통 15~25KB).
2. **무료 이미지 검색** — 품목 옆 "🔍 무료 검색"을 누르면 [Openverse](https://openverse.org)
   (CC 라이선스 이미지를 모아둔 공개 검색 API, 별도 가입·키 필요 없음)에서 검색해 바로 등록할 수
   있습니다. 상업적 이용과 가공(자르기)이 허용된 라이선스만 보여주고, 각 썸네일에 라이선스를
   표시합니다 — **CC0(초록)**은 출처 표시 없이 자유롭게 쓸 수 있고, 나머지(주황, 예: BY·BY-SA)는
   원 저작자 표시가 필요한 라이선스라는 뜻입니다. Openverse는 영어 검색어일 때 결과가 훨씬 많아,
   `lib/produceDictionary.ts` 에 담아둔 과일·채소·식료품 한→영 사전으로 품목명을 자동 번역해
   미리 채워줍니다("사과 (부사)" → `apple`처럼 괄호 속 품종명은 떼고 매칭). 사전에 없는 낯선
   품목은 억지로 번역하지 않고 검색창을 빈칸으로 두어 직접 입력하게 합니다. 고른 이미지는
   서버가 직접 받아 sharp 로 똑같이 정사각 900px JPEG 으로 줄여 저장하므로, 어느 경로로
   등록하든 결과물 용량은 비슷합니다.

두 경로 모두 별도 스토리지 서비스 없이 Postgres 에 저장하고
`/api/products/[id]/image?v=<버전>` 으로 서빙하는데, 응답에 1년짜리 immutable 캐시 헤더가 붙어
첫 요청 뒤에는 CDN 이 처리합니다. 사진을 바꾸면 버전이 올라가 URL 이 바뀌므로 캐시가 자동으로 갱신됩니다.
품목 수가 수백 개 규모로 커지면 Vercel Blob 같은 전용 스토리지로 옮기는 편이 낫습니다.

**수량 제한**: `daily_items.limit_qty` (비우면 무제한).
고객 화면에서는 담는 즉시 "남은 수량"이 줄어들고, 0이 되면 + 버튼이 잠깁니다.

**세일과 특별 구역**: `daily_items` 의 `sale_price` 가 있고 `sale_starts_at ~ sale_ends_at`
안에 들어오면 그 가격으로 팝니다(둘 다 비우면 하루 종일). 관리자는 **종료 시각을 직접 고르지
않고, 시작 시각 + 몇 시간 지속** 으로 입력합니다 — 예: 시작 10:00 + 3시간 → 자동으로 13:00
종료로 계산되어 저장됩니다. 시작 시각만 정하고 지속 시간을 비우면 시작 이후 끝없이 진행되고,
시작 시각도 비우면 하루 종일입니다. 시각은 판매 날짜 기준 한국 시간으로 해석해
`timestamptz` 로 저장합니다.
`highlight` 로 고객 화면 위쪽 구역을 정합니다 — `timesale` / `limited` / `best`.
타임세일은 이미 끝난 것이 계속 붙어 있지 않도록 **진행 중이거나 시작 전인 것만** 노출합니다.

주문 저장 시 가격은 화면에서 받은 값을 믿지 않고 **트랜잭션 안에서 세일 시간대까지 따져
다시 계산**합니다. 그래서 세일이 끝나는 순간에 눌러도 정가로 정확히 저장되고,
지난 주문의 금액은 당시 가격 그대로 남습니다.

**세일 설정은 상단 일괄 툴바에서**: 판매목록 화면에서 품목마다 세일 입력칸을 따로 두면
화면이 한없이 길어지므로, 목록 위 툴바에서 여러 품목을 체크한 뒤 세일가·시작시간·지속시간·
노출 구역을 한 번에 적용합니다("선택 품목에 적용"). 해제도 선택 후 "세일 해제" 한 번이면
전부 정가로 돌아갑니다.

**매출 통계** (`/admin/stats`): 기간(오늘/최근 7일/최근 30일/이번 달/직접 선택)을 고르면
매출·주문건수·평균 객단가·미입금 합계, 날짜별 판매현황(막대그래프 포함), 품목별 판매현황을
보여줍니다. 일별 판매현황에서 날짜를 누르면 기간이 그 하루로 좁혀지면서 품목별 판매현황도
"그날 무엇이 얼마나 팔렸는지"로 바뀝니다 — 별도 화면 없이 기간 범위(from=to)로 같은 쿼리를
재사용하는 방식입니다. 하루로 좁힌 뒤에는 우상단 **"← 기간 전체로"** 로 원래 보던 범위로
돌아갈 수 있습니다(진입 전 범위를 `back_from`/`back_to` 쿼리로 함께 넘겨서 기억합니다).
**"엑셀로 내보내기"** 를 누르면 지금 보고 있는 기간의 일별·품목별 판매현황을 CSV 파일로
내려받습니다(UTF-8 BOM 포함이라 엑셀에서 열어도 한글이 깨지지 않습니다).

**담은 품목 확인 + 담기 피드백**: 그리드만으로는 지금 뭘 담았는지 한눈에 보기 어려워서,
하단 고정바의 "N가지 담음 · 내역 보기"를 누르면 담은 품목을 이름·수량·소계로 나열한
바텀시트가 뜨고 여기서 바로 수량을 고치거나 뺄 수 있습니다(`app/order/CartSheet.tsx`).
또한 `+` 를 누를 때마다 "사과 2개 담았어요" 같은 토스트가 잠깐 떴다 사라져서, 실수로
빈 탭을 했는지 바로 알 수 있게 했습니다.

**당일 주문 수정**: `/order` 의 주문 내역 카드마다(당일·확정·미입금 건만) "수정" 버튼이
있습니다. 누르면 그 주문의 품목을 이름으로 오늘 판매목록과 매칭해 미리 채우고(수정 대상
주문 자신이 이미 차지한 수량은 남은 수량에 되돌려 더해줘서 원래 담긴 만큼 정확히
복원됩니다), 픽업/배달·주소·메모도 그대로 불러옵니다. 제출은 새 주문(`placeOrder`)이 아닌
별도 액션(`updateMyOrder`)으로 처리되어 기존 주문을 덮어씁니다.

**주문 전 최종 확인**: "주문하기"를 눌러도 바로 접수되지 않고 "주문내역이 맞습니까?"
화면(`OrderConfirmModal`)이 먼저 뜹니다. 담은 품목·수령방법·주소·메모·합계를 한 번 더
보여주고, "네, 주문할게요"를 눌러야 실제로 제출됩니다. 배달 주소처럼 브라우저가 검사해야
할 필수값은 확인 화면을 열기 전에 `reportValidity()` 로 먼저 걸러냅니다.

**카테고리·검색**: 고객 화면은 품목함에 등록한 분류를 그대로 칩으로 보여주고, 이름으로
검색할 수 있습니다. 검색이나 분류를 쓰는 동안에는 위쪽 특별 구역이 잠시 숨습니다. 카드는
한 줄에 3개씩 배치해 세로 스크롤을 줄였습니다.

**실시간 주문 알림(롤링 티커)**: 첫 화면과 `/order` 상단에 "○○님이 △△를 담았어요"가
2.8초마다 한 줄씩 돌아갑니다(`components/OrderFeedTicker.tsx`). 오늘 실제 주문과 관리자가
`/admin`의 "설정 → 실시간 주문 알림"에서 등록한 예시 항목을 번갈아 섞어서 보여주는데,
정확한 시간 순서보다 "계속 움직이는 느낌"이 목적이라 절대시간은 표시하지 않습니다. 갓
오픈해 실제 주문이 적을 때 예시 몇 개를 넣어두면 첫인상이 훨씬 활기차 보입니다.

**주문 마감 시간**: `/admin`의 "설정"에서 마감 시각(`HH:MM`)을 정하면, 그 시각(한국시간)
이후로는 새 주문과 주문 수정이 막힙니다. 고객 화면에도 마감 배너가 뜨고 제출 버튼이
잠기지만, 진짜 방어선은 서버 액션(`placeOrder`/`updateMyOrder`) 안의 검사입니다 —
브라우저에서 버튼을 강제로 눌러 우회해도 서버가 다시 막습니다. 비워서 저장하면 마감
없이 하루 종일 주문을 받습니다. 주문 취소는 마감 시간과 무관하게 계속 가능합니다.

**상단 헤더**: 가게 이름 옆에 지점명을, 그 아래 줄에 연락처(누르면 바로 전화)와
카카오톡 오픈채팅 아이콘(새 탭으로 열림)을 넣을 수 있습니다. `.env` 에 값이 없으면
해당 항목은 아예 나타나지 않습니다 — `NEXT_PUBLIC_SHOP_BRANCH`,
`NEXT_PUBLIC_SHOP_PHONE`, `NEXT_PUBLIC_OPENCHAT_URL`.
남은 수량은 그날의 확정 주문 합계를 빼서 계산하고, 주문 저장은 트랜잭션 안에서
해당 행을 `FOR UPDATE`로 잠근 뒤 다시 세기 때문에 **동시에 마지막 1개를 담아도 한 명만 성공**합니다.

---

## 로컬에서 돌리기

```bash
npm install
cp .env.example .env.local   # 값 채우기
npm run migrate              # 테이블 생성
npm run seed                 # (선택) 샘플 품목 8개 + 오늘 판매목록
npm run dev
```

`.env.local` 항목:

| 변수 | 설명 |
| --- | --- |
| `DATABASE_URL` | Postgres 연결 문자열. Neon 주소면 서버리스 드라이버, 아니면 일반 `pg` 드라이버를 자동으로 씁니다 |
| `ADMIN_PASSWORD` | 관리자 로그인 비밀번호 |
| `SESSION_SECRET` | 쿠키 서명용 키. `openssl rand -base64 32` |
| `NEXT_PUBLIC_SHOP_NAME` | 화면에 표시할 가게 이름 |

로컬에 Postgres가 없으면:

```bash
brew install postgresql@17 && brew services start postgresql@17
createdb fruit_dev
# DATABASE_URL="postgresql://$(whoami)@localhost:5432/fruit_dev"
```

## Vercel 배포

1. Vercel에서 이 GitHub 저장소를 Import
2. **Storage → Neon(Postgres) 연결** → `DATABASE_URL` 자동 주입됨
3. Settings → Environment Variables 에 나머지 3개 추가
   - `ADMIN_PASSWORD`
   - `SESSION_SECRET`
   - `NEXT_PUBLIC_SHOP_NAME`
4. 첫 배포 후 로컬에서 운영 DB에 테이블 생성:

```bash
DATABASE_URL="<Neon 연결 문자열>" npm run migrate
```

## 알아둘 점

- 날짜는 서버 시간대와 무관하게 **한국 시간 기준**으로 계산합니다 (`lib/util.ts`의 `todayKST`).
- **닉네임은 가게 전체에서 유일**합니다 (`lower(nickname)` 유니크 인덱스). 고객이 명단에서
  자기를 찾아야 하므로 `301호 민지엄마`처럼 구분되는 이름으로 등록해주세요.
  이미 있는 닉네임으로 등록하려 하면 관리자 화면에서 막힙니다.
- 첫 화면 명단에는 **닉네임만** 나옵니다. 휴대폰 뒷자리는 고객 화면 어디에도 노출되지 않고,
  관리자 화면에서만 보입니다.
- 이름이 남에게 보이면 곤란한 상황이라면 실명 대신 `301호`처럼 별칭으로 등록해두세요.
- 주문 이력이 있는 품목·고객은 삭제 대신 보관 처리되어 과거 기록이 남습니다.
- 관리자 인증은 비밀번호 1개 + 서명된 쿠키(30일)입니다. 여러 직원이 각자 로그인해야 한다면
  계정 테이블을 따로 두는 편이 낫습니다.
